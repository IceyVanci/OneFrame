**日期**：2026-07-02

## 一、Manifest 清单法优化首页缩略图选取

### 背景

V1.13 实现的首页缩略图随机选取机制存在两个问题：

1. **首页闪烁**：HTML `<img src>` 直接指向 `Sample/` 目录下的默认图片，浏览器先加载默认图，`initHomepageThumbnails()` 异步替换为随机图片后导致图片闪烁两次。
2. **回退模式性能差**：当 Electron IPC 不可用时（如 Web/NAS 部署），回退到 Image 对象逐个探测，最多 99×2×13 = 2,574 次加载请求。

### 优化方案

用 **manifest 清单法** 替代暴力探测，同时引入透明占位符消除闪烁。

#### 1. 新建 `src/renderer/Sample/sample-manifest.json`

静态 JSON 清单，列出所有实际存在的样本文件按样式分组：

```json
{
  "version": 1,
  "generated": "2026-07-02",
  "samples": {
    "TypeA": ["001", "022", "032"],
    "TypeB": ["002", "017", "028"],
    ...
  }
}
```

当前共 34 个样本文件，覆盖全部 13 种样式。

#### 2. 首页闪烁消除

将 13 个样式卡片的 `<img src>` 从实际图片路径改为 **透明 GIF data URI 占位符**，原始路径移至新增的 `data-fallback-src` 属性：

```html
<!-- 之前 -->
<img src="Sample/022-TypeA-sample_compressed.jpeg" ...>

<!-- 之后 -->
<img src="data:image/gif;base64,R0lGODlhAQABAIAAAAAAAP///yH5BAEAAAAALAAAAAABAAEAAAIBRAA7" 
     data-fallback-src="Sample/022-TypeA-sample_compressed.jpeg" ...>
```

页面加载时卡片区域为透明，随机化完成后一次性写入最终图片，完全消除闪烁。

#### 3. 重写 `thumbnail-selector.js`

从 287 行精简至 195 行，采用三级回退策略：

```
策略 1：manifest 清单（IPC 优先，fetch 回退）→ 1 次请求
策略 2：IPC 文件列表回退（Electron 环境）
策略 3：data-fallback-src 静态回退
```

**新增函数：**
- `fetchManifest()` — 获取 manifest，优先 Electron IPC，失败时 fetch
- `selectRandomFromManifest(manifest, metaList, sampleBasePath)` — 从清单中随机选取，Fisher-Yates 洗牌 + 全局 imageId 去重

**移除函数：**
- `getDefaultImageIdList()` — 不再需要遍历 99 个 ID
- `collectCandidatesForStyle()` — 不再需要逐个 Image 探测
- `checkFileExists()` — 不再需要 Image 对象探测

**保留函数：**
- `styleIdToTypeName()`、`buildCandidatePath()`、`shuffle()`
- `collectCandidatesFromFileList()` — IPC 文件列表回退模式
- `assignUniqueIdThumbnails()` — 全局去重分配
- `buildStyleThumbnailMeta()` — 增加 `data-fallback-src` 优先读取逻辑

#### 4. 自动更新 manifest

新建 `scripts/generate-manifest.js` 脚本，自动扫描 `Sample/` 目录生成清单。有变化才写入，无变化跳过。

集成到 `package.json` 的 `dev` 和 `build` 命令中：

```json
"dev": "node scripts/generate-manifest.js && electron . --dev",
"build": "node scripts/generate-manifest.js && electron-builder --win portable"
```

每次 `pnpm dev` 或 `pnpm run build` 时 manifest 自动更新，也可手动运行 `pnpm run generate-manifest`。

## 二、IPC 新增 manifest 读取端点

为支持 manifest 清单法，在主进程新增 IPC 端点：

- `src/main/main.js`：新增 `get-sample-manifest` IPC 处理器，读取并解析 `sample-manifest.json`
- `src/main/preload.js`：暴露 `getSampleManifest` API

保留原有 `get-sample-files` 端点作为兼容回退。

## 三、性能对比

| 指标 | 优化前 | 优化后 |
|------|--------|--------|
| HTTP 请求数（Web/NAS） | 最多 2,574 次 HEAD | **1 次 GET** |
| 首页闪烁 | 有 | **无**（透明占位 → 一次性写入） |
| 回退模式风险 | 2,574 次 Image 加载可能卡顿 | **0 次**（直接用 fallback-src） |
| 代码行数 | 287 行 | **195 行**（-32%） |
