## 一、Type I 样式创建

### 设计说明

新增 Type I 样式（极简叠加文字），基于 Type H（全画幅叠加文字）进一步简化。

**设计目标：** 最大化照片展示面积，仅保留品牌 Logo 和署名，适合纯净的照片展示场景。

**与 Type H 的关键差异：**

| 特性 | Type H | Type I |
|------|--------|--------|
| Logo 位置 | 底部居中 | 顶部居中 |
| 底部内容 | 日期 + 参数 + 机型 + 署名 | 仅署名 |
| 编辑面板 | 隐藏边框/比例/开关，显示 Logo + 文字颜色 | 额外隐藏设备型号/拍摄参数/时间 |
| 默认署名 | 用户手动输入 | 自动填入 "OneFrame" |
| 纵向图片 | 无特殊处理 | 底部字体增大 50% |

**Type I 布局：**
```
┌──────────────────────────────┐
│         [Logo]  (顶部居中)   │
│                              │
│         照片 100% 填满画布    │
│                              │
│          © OneFrame          │  ← 底部仅署名
└──────────────────────────────┘
```

## 二、Type I 特性细节

### 编辑面板

Type I 编辑面板仅显示以下内容：
- Logo 选择区域
- 署名输入框（默认值 "OneFrame"）
- 文字颜色选择（黑/灰/白，默认白色）

隐藏的编辑项：
- 边框颜色/高度/比例
- 设备型号
- 拍摄参数
- 时间

### 纵向图片适配

纵向图片（高度 > 宽度）时：
- 底部字号增大 50%（预览端从 `frameWrapper` 宽度计算基准字号后 × 1.5）
- 导出端同样检测 `canvasHeight > canvasWidth` 并增大字号

### 默认署名

Type I 署名默认值为 "OneFrame"：
- `type-i-preview.js`：`settings.signatureText || 'OneFrame'`
- `type-i-export.js`：`settings.signatureText || 'OneFrame'`
- `type-i-editor-panel.js`：编辑面板打开时自动填入 "OneFrame"

### 字号计算修复

修复纵向图片预览时字号累乘的 bug：
- **问题**：每次 `updateContentPreview` 调用时读取 `borderContent.style.fontSize`（上次已 × 1.5 的值），再 × 1.5 写回，导致输入一个字字号就增大一次
- **修复**：改为从 `frameWrapper.style.width` 重新计算基准字号 `14 * fwWidth / 900`，确保每次调用都基于原始值

## 五、Type J 样式创建

### 设计说明

新增 Type J 样式（署名+三栏参数行），基于 Type H（全画幅叠加文字）调整布局。

**设计目标：** 不显示 Logo，署名移到原 Logo 位置，参数行重新布局为三栏（左机型/中参数/右时间）。

**与 Type H 的关键差异：**

| 特性 | Type H | Type J |
|------|--------|--------|
| Logo | 底部居中显示 | 不显示 |
| 署名位置 | 底部第三行 | 原 Logo 位置（底部第一行） |
| 署名字号 | 小于参数（0.8571em） | 与参数相同 |
| 参数行 | 单行居中（日期 \| 参数 \| 机型） | 三栏布局（左机型/中参数/右时间） |
| 机型名称 | 不含厂商 | 含厂商（如 "Sony A7M4"） |
| 编辑面板 | 隐藏边框/比例/开关，显示 Logo + 文字颜色 | 额外隐藏 Logo 区域和设备型号输入 |

**Type J 布局：**
```
┌──────────────────────────────────────┐
│                                      │
│         照片 100% 填满画布            │
│                                      │
│         © OneFrame                   │  ← 署名（原 Logo 位置，同参数字号）
│ Sony A7M4  50mm f/2.8 1/125 ISO400  2024/01/01 │  ← 三栏布局
└──────────────────────────────────────┘
```

参数行三栏布局：
- 左栏（5%起）：机型名称（含厂商，如 "Sony A7M4"）
- 中栏（居中）：焦距 光圈 快门 ISO
- 右栏（95%止）：时间（YYYY/MM/DD）

## 六、Type J 导出定位修复

### 问题

导出图像中文字位置比预览更高。

### 根因

预览端和导出端使用了不同的定位方式：

| | 预览（CSS） | 导出（Canvas） |
|--|-------------|----------------|
| 锚定方式 | 底部锚定 `bottom: 3%` | 中心锚定 `textCenterY = 92.5%` |
| line-height | `1`（CSS `line-height: 1`） | `1.4`（JS `fontSize * 1.4`） |
| 行间距 | `0.5em`（CSS `margin-bottom: 0.5em`） | `6 * baseScale`（JS 固定值） |

预览用 CSS `bottom: 3%` 底部锚定，文字组底部边缘在画布 97% 处向上排列。
导出沿用 Type H 的 15% 文字区域中心定位逻辑，文字组中心在画布 92.5% 处，导致整体偏高。

### 修复

修改 `type-j-export.js` 的 `drawBorderContent` 函数（第 67~103 行）：
1. 定位方式从"15% 区域中心"改为"底部锚定 `bottomAnchorY = canvasHeight * 0.97`"，与 CSS `bottom: 3%` 对齐
2. `lineHeight` 从 `fontSize * 1.4` 改为 `fontSize`，与 CSS `line-height: 1` 一致
3. 间距从 `baseScale * 6` 改为 `fontSize * 0.5`，与 CSS `margin-bottom: 0.5em` 一致
4. 布局改为从底部向上排列：参数行在下（锚点处），署名在上
