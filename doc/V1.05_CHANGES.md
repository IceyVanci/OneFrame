## 一、Type F 纵向图片自适应

### 问题描述

Type F（画中画风格）在导入纵向图片（高度 > 宽度）时，上下白色留白区域过大，照片展示区域偏小，导致纵向图片的视觉效果不理想。

### 修改说明

为 Type F 增加纵向图片自适应逻辑：当导入图片为纵向时，图框上下的白色部分减少一半，照片区域相应增大。

| 场景 | 顶部白色 | 照片区域 | 底部文字区 |
|------|---------|---------|-----------|
| 横向图片（不变） | 5% | 80% | 15% |
| 纵向图片（新增） | 2.5% | 90% | 7.5% |

### 修改详情

#### 1. `type-f-preview.js` — `calcSize()` 函数

```javascript
// 修改前：固定使用 0.8
const canvasHeight = Math.round(naturalHeight / 0.8);

// 修改后：纵向图片使用 0.9（照片占 90%）
const isPortrait = naturalHeight > naturalWidth;
const heightRatio = isPortrait ? 0.9 : 0.8;
const canvasHeight = Math.round(naturalHeight / heightRatio);
```

返回值增加 `isPortrait` 字段。

#### 2. `type-f-preview.js` — `updatePreview()` 函数

```javascript
// 纵向图片：覆盖 CSS 默认的 top:5% height:80% 为 top:2.5% height:90%
const isPortrait = imgDimensions.naturalHeight > imgDimensions.naturalWidth;
if (isPortrait) {
  state.img.style.top = '2.5%';
  state.img.style.height = '90%';
}
if (state.borderContent) {
  state.borderContent.style.height = isPortrait ? '7.5%' : '';
}
```

#### 3. `type-f-export.js` — `renderImage()` 函数

```javascript
// 修改后：区分横向/纵向
const isPortrait = img.naturalHeight > img.naturalWidth;
const heightRatio = isPortrait ? 0.9 : 0.8;
const canvasHeight = Math.round(img.naturalHeight / heightRatio);
const photoY = canvasHeight * (isPortrait ? 0.025 : 0.05);
const photoHeight = canvasHeight * (isPortrait ? 0.90 : 0.80);
```

#### 4. `type-f-export.js` — `drawBorderContent()` 函数

签名增加 `isPortrait` 参数，文字区域比例调整：

```javascript
const textRatio = isPortrait ? 0.075 : 0.15;
const textAreaHeight = canvasHeight * textRatio;
const textAreaTop = canvasHeight * (1 - textRatio);
```

### 修改文件

| 文件 | 变更类型 | 说明 |
|------|----------|------|
| `src/renderer/js/styles/type-f-preview.js` | 修改 | `calcSize()` 纵向图片使用 0.9 计算画布高度；`updatePreview()` 纵向图片时覆盖 CSS 默认百分比值 |
| `src/renderer/js/styles/type-f-export.js` | 修改 | `renderImage()` 纵向图片使用 0.9 计算画布高度；`drawBorderContent()` 接收纵向标记，调整文字区域比例 |

### 修复效果

| 场景 | 修复前 | 修复后 |
|------|--------|--------|
| 横向图片导入 | ✓ 正确 | ✓ 正确（不变） |
| 纵向图片导入 | ✗ 白色区域过大 | ✓ 白色区域减半 |
| 纵向图片导出 | ✗ 白色区域过大 | ✓ 白色区域减半 |
| 窗口缩放 | ✓ 正确 | ✓ 正确 |
| 其他样式 | ✓ 不受影响 | ✓ 不受影响 |

## 二、Type E 预览文字缩放

### 问题描述

Type E 预览使用 CSS 固定像素字号（月份 48px、年份 24px、参数 18px），当 `calcSize()` 根据预览区域大小缩放 frameWrapper 时，文字不会跟随缩放。这导致小窗口时文字相对过大，大窗口时文字相对过小。

### 修改说明

将 CSS 中的 `px` 字号改为 `em` 单位（相对于基准字号），在 `updateFrameWrapper()` 中根据 frameWrapper 宽度动态设置基准字号到 borderContent。

### 修改详情

#### 1. `type-e.css` — font-size 改为 em

```css
/* 修改前 */
.type-e-month  { font-size: 48px; margin-bottom: 8px; }
.type-e-year   { font-size: 24px; }
.type-e-param-line { font-size: 18px; }

/* 修改后 */
.type-e-month  { font-size: 2em;    margin-bottom: 0.333em; } /* 48/24=2 */
.type-e-year   { font-size: 1em;    } /* 24/24=1 */
.type-e-param-line { font-size: 0.75em; } /* 18/24=0.75 */
```

#### 2. `type-e-preview.js` — `updateFrameWrapper()`

```javascript
// 新增：动态设置基准字号
if (state.borderContent) {
  const baseFontSize = Math.max(8, Math.round(24 * squareSize / 900));
  state.borderContent.style.fontSize = `${baseFontSize}px`;
}
```

#### 3. `type-e-preview.js` — `handleLogoLoad()`

```javascript
// 修改前：硬编码 24
const yearFontSize = 24;

// 修改后：从 borderContent 读取动态字号
const baseFontSize = state.borderContent
  ? parseFloat(getComputedStyle(state.borderContent).fontSize)
  : 24;
const yearFontSize = baseFontSize;
```

### 缩放公式

基准字号 = `24 × squareSize / 900`（squareSize 为 frameWrapper 显示宽度），900px 为原始设计基准宽度。

| 组件 | 字号计算 |
|------|---------|
| 月份 | `baseFontSize × 2em` |
| 年份 | `baseFontSize × 1em` |
| 参数 | `baseFontSize × 0.75em` |

### 修改文件

| 文件 | 变更类型 | 说明 |
|------|----------|------|
| `src/renderer/css/type-e.css` | 修改 | font-size 从 px 改为 em（month: 2em, year: 1em, param: 0.75em） |
| `src/renderer/js/styles/type-e-preview.js` | 修改 | `updateFrameWrapper()` 添加基准字号设置；`handleLogoLoad()` 从 borderContent 读取动态字号 |

### 注意事项

导出端不需要修改，因为导出使用独立的 `TYPE_E_STYLES` 基准字号（48/24/18px）+ `scale = canvasWidth / previewSquareSize` 缩放比。

## 三、Type G 样式创建

### 设计说明

新增 Type G 样式，布局与 Type F 类似（白色背景 + 顶部留白 + 中部照片 + 底部文字区），但有以下差异：

- **第一行**：显示厂商 Logo（替代 Type F 的 "Shot on 型号" 文字）
- **第二行**：显示 `拍摄日期 | 拍摄参数 | 相机名称`（三部分竖线分隔，全部黑色）
- **第三行**：显示署名
- **编辑面板**：恢复 Logo 选择区域，隐藏所有显示开关（所有元素默认显示）
- **机型名称**：只显示型号名称，不包含品牌前缀（如 "A7M4" 而非 "Sony A7M4"）

| 场景 | Logo 最大高度 | 宽度 |

### 已知问题

**预览模式下 Logo 无法正确水平居中**：

- **现象**：导出端 Logo 居中正确，但预览端 Logo 水平位置偏移
- **根因**：预览端使用 HTML `<img>` 标签显示 SVG Logo，CSS `text-align: center` + `display: inline-block` 居中方案依赖 SVG 的固有尺寸属性。部分 SVG 缺少 `viewBox` 或 `width/height` 属性，导致浏览器无法正确计算固有宽度，居中失效
- **导出端对比**：导出使用 Canvas API `drawImage()`，在绘制前通过 `img.naturalWidth` 获取实际像素宽度，计算 `x = centerX - drawWidth / 2` 精确居中
- **待修复方向**：在预览端 JS 中使用 Image 对象预加载 SVG，获取 `naturalWidth/naturalHeight` 后设置精确的 `width` 和 `height` inline style，确保 `text-align: center` 能正确居中
